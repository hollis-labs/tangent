# Using the Inbox

Open Tangent's root URL to see Inbox.

Approvals, documents, agent turns and structured interactions appear in one
arrival queue. The default view shows pending items, oldest first. Use Type to
view a subset, Search to find a request or agent, and View to browse History or
All. Newest-first sorting does not change an item's stored arrival position.

Select a request to open its body. An approval queue, form, diff or design
review uses its own interactive view inside the main pane. That pane grows with
the browser window; Expand interaction hides the queue for more space. On a
small screen, selecting a request uses the whole content area; Back to inbox
returns to the list. Arrow keys, Home and End navigate queue rows.

Use the body's explicit action to reply, decide, acknowledge or archive. A
successful action leaves the confirmed response visible instead of moving you
to another request. For a structured interaction, Sending your response means
Tangent has not yet confirmed it. A rejected submission returns to your filled-in
form with the reason; it is not a saved answer.

Completed items move out of Pending but remain in History. Opening the same
item after refreshing shows its original request and saved response. Responses
are read-only; viewing a previous decision does not make it again. Stored
content remains subject to Tangent's retention policy.

Documents can be marked read without resolving them. A document requesting an
acknowledgement offers that action; Archive removes an unanswered document from
the pending queue. Dismissing an agent turn does not send the agent an answer.

An item link (`/inbox/items/<interactionID>`) opens that exact request. A room
link (`/r/<roomID>`) opens the latest request in that room. Navigation stays
compact even when agents create new rooms.

Channels remains the ongoing conversation surface. An agent must open a relay
channel and receive messages for replies there to reach it. Inbox is where you
handle individual requests.

For agent setup and tool contracts, see [MCP integration](mcp-integration.md).
